↗ Experience is available to the team

After a Megaladata task is prepared successfully, its messages and tool results are stored in the shared Dock archive after secrets are removed. The archive is available to other Dock participants.

⌂ The browser stays local

Each task has its own browser profile. Profiles and binary files are not part of the Dock archive; the agent's personal memory provider is kept.

Full instructions ↓
Where do I get a Dock client key?

Ask the administrator of your Megaladata Dock installation. They issue the client key of the shared account. Enter it in the local installation wizard — this page has no key form. Signing in to the Megaladata application itself needs a separate account.

Which operating systems are supported?

Megaladata Dock runs on Windows 11 x64, macOS with Apple Silicon (M1 and newer), and Linux x64 with a graphical environment. A Mac needs an Apple Silicon processor. Check it in the Apple menu → About This Mac.

Which nodes already have ready scripts?

Text file import, Field Features, Row Filter, Join, Union, Calculator, Grouping, Sort, Replacement, Duplicates, Date and time, Missing values, Unpivoting, and text file export. The verified modes of these nodes are supported; other modes and nodes are added gradually.

Which files can be attached to a task?

For automatic import in this RC, use CSV, TSV, or a text file: up to 8 attachments, up to 16 MiB each, and up to 64 MiB in total. Dock uploads a separate copy into the Megaladata working folder and keeps existing files. XLSX and JSON transfer is provided, but ready import handlers for them are not in this RC. Messenger attachments are not checked yet.

Which model does Megaladata Dock use?

Codex or Hermes uses the model configured in the agent itself. Megaladata Dock adds tools for working with Megaladata and does not change the current model configuration.

Why does the Megaladata address need testable?

The ?testable=true parameter turns on interface element identifiers the agent uses to find buttons and nodes. If the address already contains a question mark and other parameters, use &testable=true. The parameter itself does not replace signing in.

What if the connection fails?

Check the VPN if you use an internal stand, the Megaladata address, the testable=true parameter, and the client key. On Linux, make sure the agent is running in a graphical session. Then, in a new task, ask: “Check the Megaladata Dock diagnostics and explain what blocks the connection.” When you contact an administrator, attach the error text without keys.

Can I continue an existing scenario?

Yes. Tell the agent which package to use and the specific change: which field, node, or check to add. For a first look, it is convenient to ask to save the result as a new copy and then compare it with the original package.

How do I update, roll back, or remove the plugin?

To update, download the new release, unpack it into a separate folder, and run the wizard again for the same agent and profile. From the unpacked set you can use the commands below. Codex is selected here; switch the agent in the installation section.

Update while keeping settings
./install.sh --agent codex
Roll back to the previous installation
./install.sh --agent codex --rollback
Remove the selected agent's plugin
./install.sh --agent codex --uninstall

Rollback is available when there was a previous installation. For a separate Hermes profile, repeat --hermes-home. Removing the plugin keeps local artifacts and the shared server history.
